# REST API GEL / FLOW

Базовый путь — `/api/`. Запросы JSON, кроме загрузки файла импорта (`multipart/form-data`). Денежные и складские десятичные числа возвращаются строками; денежная точность — 2 знака, материалы и остатки — 3. Дата/время — ISO 8601 UTC. ID — целые числа. Списки возвращаются массивами, без конверта пагинации.

## Аутентификация

Используются серверные сессии Django, cookie `sessionid` и CSRF. JWT/API-ключей нет. Сначала выполните `GET /api/me/` либо откройте `/`: сервер установит cookie `csrftoken`. При каждом `POST`, `PATCH`, `PUT`, `DELETE` передавайте заголовок `X-CSRFToken` со значением этой cookie и cookie сессии. Вход меняет CSRF-токен, поэтому после него прочитайте cookie заново. Приложение рассчитано на один origin; CORS для посторонних доменов не включён.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health/` | Доступен без входа, выполняет проверку соединения с БД, ответ `{"status":"ok"}` |
| GET | `/me/` | `{user, permissions}`; без входа `user:null` |
| POST | `/login/` | `{username,password}` → `{user,permissions}` |
| POST | `/logout/` | Завершение текущей сессии |
| GET | `/dashboard/` | `{stats,stage_counts,recent_orders,low_stock}`, с учётом роли |

Пример вызова из страницы CRM (браузер):

```js
await fetch('/api/me/');
const csrf = () => decodeURIComponent(document.cookie.split('; ')
  .find(v => v.startsWith('csrftoken=')).split('=').slice(1).join('='));
const response = await fetch('/api/login/', {
  method: 'POST', credentials: 'same-origin',
  headers: { 'Content-Type': 'application/json', 'X-CSRFToken': csrf() },
  body: JSON.stringify({ username: 'superadmin', password: 'DemoGel2026!' })
});
console.log(await response.json());
// Для следующей записи снова вызовите csrf(): вход ротирует токен.
```

Ответы ошибок: `400` — валидация или неверный пароль; `403` — нет сессии/прав либо CSRF; `404` — объект отсутствует или недоступен; `429` — лимит запросов; `503` — окно восстановления. Формат — `{"detail":"..."}` либо объект ошибок по полям. Вход ограничен 10 попытками в минуту на IP; при штатном memory-cache лимит действует в пределах процесса. Для общего ограничения нескольких web-workers нужен общий cache или ограничение на reverse proxy.

## Клиенты и сообщения

| Метод | Путь | Доступ |
| --- | --- | --- |
| GET, POST | `/customers/` | superadmin, admin, manager |
| GET, PATCH, PUT | `/customers/{id}/` | То же, менеджеру — свой клиент; очередь доступна только для просмотра |
| POST | `/customers/{id}/assign/` | superadmin, admin |
| GET, POST | `/customers/{id}/messages/` | Администраторы и закреплённый менеджер |

Создание клиента:

```json
{"name":"Студия LUNA","phone":"+79991234567","email":"","channel":"manual"}
```

Для защиты от дублей нужен телефон или email. `manager` в теле создания/редактирования не назначается: новый контакт попадает в очередь. `GET /customers/?search=Луна` ищет по имени, телефону или email.

Назначение/передача — `{"manager_id":3}`; `null` возвращает клиента в очередь. При передаче меняется ответственный у его заказов. ID должен относиться к активному пользователю роли `manager`. Сообщение — `{"text":"Согласован оттенок"}`. Отправка доступна для `channel=manual`; внешние каналы отклоняются, пока адаптеры не подключены. История содержит `author`, `author_name`, `incoming`, `channel`, `created_at`.

## Заказы и производство

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET, POST | `/orders/` | Просмотр; создание — администраторы и менеджер своего клиента |
| GET | `/orders/{id}/` | Карточка, `total`, `paid`, `debt` |
| POST | `/orders/{id}/start/` | Атомарное списание и создание заданий |
| GET | `/tasks/`, `/tasks/{id}/` | Администраторы и сотрудники своего отдела |
| POST | `/tasks/{id}/advance/` | Приёмка, контроль качества или доработка |

Стандартный заказ:

```json
{"customer":1,"kind":"standard","product":2,"quantity":24,"unit_price":"590.00","comment":"Добавить каталог"}
```

Индивидуальный заказ:

```json
{"customer":1,"kind":"custom","recipe":1,"quantity":120,"unit_price":"650.00","color_parameters":"Пыльная роза без шиммера","comment":"Выкраска согласована","reference_photo":"https://example.ru/reference.jpg"}
```

Клиент предварительно должен иметь менеджера. Один заказ содержит один товар либо одну колеровку. `reference_photo` — только URL; бинарной загрузки фото нет. Статусы и ответственный устанавливаются сервером. Изменение, удаление и отмена запущенных заказов API не поддерживает.

`POST /start/` принимает пустой объект. Повторный запуск запрещён. Стандартный заказ списывает готовый `Product.stock` и создаёт `pick → ship`; индивидуальный — расход всех компонентов `quantity × RecipeComponent.quantity` и `color → fill → label → pick → ship`. Недостаток откатывает всю транзакцию.

Тело действия над заданием:

```json
{"action":"accept","note":""}
```

`action`: `accept`, `complete`, `reject`. Завершение и возврат требуют непустого `note`. Завершать может принявший сотрудник или администратор. Нельзя принимать `waiting` или завершённый этап. Возврат требует повторной приёмки текущего этапа, следующий остаётся заблокированным.

## Склад, каталог и рецептуры

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET, POST | `/materials/` | Материалы; создавать могут администраторы |
| GET | `/materials/{id}/` | Остаток и минимум |
| POST | `/materials/{id}/adjust/` | Администратор, ненулевая дельта и основание |
| GET | `/movements/` | Последние 1000 движений; администраторы, аналитик |
| GET, POST | `/products/` | Каталог; создавать могут администраторы |
| GET | `/products/{id}/` | Товар |
| GET | `/products/{id}/history/` | История цен/остатков; администраторы, аналитик |
| GET, POST | `/recipes/` | Состав; создавать могут администраторы и колеровщик |
| GET | `/recipes/{id}/` | Отдельная рецептура |

Новый материал: `{"sku":"JAR-30","name":"Баночка 30 мл","kind":"jar","unit":"шт","min_quantity":"100.000"}`. `kind`: `raw`, `gel`, `jar`, `packaging`. Начальный остаток всегда ноль; для прихода вызовите `/adjust/` с `{"quantity":"500.000","reason":"Поступление по накладной №12"}`. Дельта может быть отрицательной, итоговый остаток — нет.

Новый товар: `{"sku":"GEL-NEW","name":"Гель","price":"650.00","recipe":1}`. Остаток напрямую не редактируется, обновляется импортом или при списании заказа.

Рецептура:

```json
{"name":"Rose v2","description":"Расход на одну баночку 15 мл","components":[{"material":1,"quantity":"0.014"},{"material":2,"quantity":"0.001"},{"material":6,"quantity":"1.000"},{"material":7,"quantity":"1.000"}]}
```

Количество каждого компонента строго положительно, материал не повторяется. Расход задаётся в единицах материала. PATCH/DELETE рецептур нет, чтобы не менять исторические заказы. Новую формулу создавайте отдельной рецептурой с новым названием; автоматическое управление версиями API пока не предоставляет. Менеджеру разрешено чтение для выбора рецептуры заказа.

## Импорт

`POST /imports/preview/`: multipart-поле `file`, необязательное `mapping` (JSON). Форматы `.xlsx`, `.csv`, `.xml`. Ответ:

```json
{"id":1,"filename":"catalog.csv","columns":["Артикул","Наименование","Цена","Количество"],"mapping":{"sku":"Артикул","name":"Наименование","price":"Цена","stock":"Количество"},"rows":[],"errors":[],"row_count":3}
```

Предпросмотр содержит первые 100 строк, в базе сохраняется весь допустимый файл. `errors` — массив `{row,field,message}`. Затем `POST /imports/{id}/apply/` с `{"mapping":{"sku":"Артикул","name":"Наименование","price":"Цена","stock":"Количество"}}`. Ответ `{created,updated,total}`. Один предпросмотр применяется один раз. Применение атомарно; рецептуры не затрагиваются. Доступ — superadmin/admin. Образцы: [CSV](../examples/catalog.csv), [CommerceML](../examples/catalog.xml).

## Финансы

`GET /finance/` и `/finance/{id}/`: администраторы, бухгалтер, аналитик. `POST /finance/`: администраторы и бухгалтер. Записи после создания не изменяются и не удаляются через API.

```json
{"order":1,"kind":"payment","amount":"10000.00","note":"Предоплата"}
```

`kind`: `payment`, `refund`, `expense`. `amount` строго положительная. Для оплаты и возврата нужен заказ; у расхода он необязателен. Возврат ограничен чистой суммой оплат, оплата — остатком долга. `paid = payments - refunds`, `debt = quantity × unit_price - paid`.

## Резервные копии

Только superadmin. `GET /backups/` возвращает `{items,last_success,next_due,enabled}`; `items` содержит последние 100 записей. `POST /backups/create/` ставит работу в очередь и отвечает `202 {id,status}`. Проверяйте итог через GET: постановка не означает успешное создание.

`POST /backups/restore/`:

```json
{"backup_id":1,"confirmation":"ВОССТАНОВИТЬ","password":"текущий пароль главного администратора"}
```

Восстановление синхронное и может занять несколько минут. Сначала проверяется архив и создаётся защитный снимок, затем заменяется база; после успеха все сессии сбрасываются. Ответ `{restored:true,safety_backup_id,detail}`. Используйте окно обслуживания; при тайм-ауте клиента не отправляйте повторный запрос, сначала проверьте состояние сервера и журнал. Файл ключа и архив не передаются через публичный API.
