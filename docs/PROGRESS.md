# Состояние реализации

## Создано в проекте

| Этап | Реализация |
| --- | --- |
| База приложения | Django REST API, схема БД с миграцией, десять ролей, серверные права, логин/пароль без email |
| Работа с клиентом | Общая очередь, уникальный нормализованный телефон/email, закрепление и передача администратором, история сообщений |
| Заказы | Один стандартный товар или одна индивидуальная рецептура, параметры цвета, комментарий, URL референса, долг и оплаты |
| Производство | Задания по отделам, приёмка ответственным, QC через обязательный комментарий завершения, возврат на доработку |
| Склад | Сырьё, готовый гель, баночки, упаковка, корректировки с основанием, запрет отрицательных остатков, транзакционный расход |
| Финансы | Оплаты, долги, ограниченные суммой оплаты частичные возвраты, расходы |
| Каталог и импорт | XLSX/CSV/XML/CommerceML, предпросмотр, сопоставление, защита от дублей, история цен/остатков, отдельные рецептуры |
| Эксплуатация | Аудит, внутренние уведомления, фоновые задачи, 12-часовые копии от последнего успеха, шифрование, retention, проверка и восстановление |
| Интерфейс | Русская адаптивная web/PWA, разделы по ролям, общий сервер для компьютеров и телефонов |
| Материалы запуска | Демо, автоматические тесты, Dockerfile, Compose, lock-файл зависимостей, руководство и API |

Стандартный заказ **списывает готовый товар при запуске** и проходит `pick → ship`. Индивидуальный заказ **сразу списывает всю спецификацию**, включая баночки и упаковку, и проходит `color → fill → label → pick → ship`. Следующий этап открывается только после завершения предыдущего с записью QC. Отклонённый этап нужно принять повторно.

## Явные границы первой версии

- Заказ содержит одну позицию. Многострочная корзина не реализована.
- `reference_photo` — URL. Загрузки файлов и своего хранилища фотографий нет.
- Внешние мессенджеры представлены статусами и контрактами адаптеров. Без реализации провайдера и ключей API они не отправляют и не получают сообщения.
- 1С импортируется файлом. Постоянного протокола обмена, характеристик товаров, отдельных типов цен и многоскладского CommerceML нет.
- Нет партий, серий, сроков годности, резервов и бухгалтерской оценки запасов. Корректировка остатков не заменяет полноценную инвентаризацию.
- Нет автоматического возврата материалов при отмене уже запущенного заказа.
- Рецептуры доступны по отдельной ссылке и защищены от импорта. Автоматического интерфейса управления версиями формулы нет.
- Уведомления — внутри CRM, без мобильного push/SMS/email. Данные обновляются запросами к общему серверу, не работают в режиме офлайн.
- PWA не является нативной сборкой для магазинов приложений. Нужны HTTPS и проверка на целевых устройствах.
- Копируется база, не конфигурация сервера или внешние файлы. Независимое внешнее хранилище архивов нужно настроить отдельно. Требуется сохранить ключ расшифрования.

## Проверки и пределы подтверждения

Схема и демо проверены отдельно: миграции применяются, повторный seed не создаёт дублей, пароли работают, начальные складские остатки равны сумме движений.

Финальная проверка этой версии: **66 тестов пройдены** на Python 3.12 / SQLite. Включены CSRF при входе, права ролей, передача клиента, защита от дублей, повторный запуск и атомарность складского расхода, пять этапов производства, обязательный текст QC, долг и возвраты, импорт и его складской журнал, уведомления, шифрование и восстановление. В отдельной базе выполнено восстановление через API, в том числе когда восстановленный снимок удаляет учётную запись администратора, запросившего операцию.

Также выполнены `manage.py check`, `makemigrations --check --dry-run`, `collectstatic`, `node --check static/app.js`, `node --check static/sw.js`, `sh -n docker-entrypoint.sh` и проверка синтаксиса Compose. Главная страница, JS, CSS, PWA manifest и service worker возвращают HTTP 200 через тестовый клиент Django. Все десять ролей проходят проверку входа и сводки. Это не браузерный тест: доступный инструмент браузера в среде отсутствует.

Повторить проверки можно после настройки `.env` по README: `python -m pytest`.

Конфигурация PostgreSQL и контейнеры предоставлены, но в текущей среде не подтверждён полный запуск Docker daemon. До эксплуатации нужен прогон на целевой PostgreSQL, проверка восстановления, браузерная приёмка и проверка телефонов. Наличие исходного кода и конфигурации не означает, что эти внешние среды уже испытаны.
